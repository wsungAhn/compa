> **상태**: 결정 대기 (사용자 액션 필요: 쿠팡 파트너스 가입 여부)
> **배경**: 네이버 검색 API가 2026년 7월 종료됐다. compa의 유일한 한국 가격
> 소스였고, 후속인 NAVER API HUB에는 **쇼핑 검색이 승계되지 않았다**

## 선행조사

### ① 레포 내 검색

도구: `python pathlib` 전수 스캔(`app/scrapers/**`) + `app/core/affiliate.py` 판독.

| 이미 있는 것 | 상태 |
|---|---|
| `firecrawl_base.py` `FirecrawlBaseScraper` (동적 URL `scrape_url()` 포함) | 살아있음. 브랜드 공홈 5종이 14~17줄 서브클래스로 구현돼 있어 **새 스텔스 스크래퍼는 20줄 이내로 추가 가능** |
| `kr/coupang.py` (httpx + BeautifulSoup, `www.coupang.com/np/search`) | `SKIP_SCRAPERS`로 제외됨 (403 차단) |
| `kr/naver_shop.py` (201줄) | API 종료로 사망 |
| `kr/oliveyoung.py` (Playwright) | 403 차단으로 제외 |
| `core/affiliate.py` | Amazon `tag`·Rakuten 링크 변환은 구현. **쿠팡 딥링크 없음** |
| `core/proxy.py` | httpx 프록시 훅 존재 |

즉 **수집 인프라(스텔스·제휴링크·수집 파이프라인)는 이미 있고, 살아있는 KR
데이터 소스만 없다.**

### ② 외부 선행작업 — 라이브 실측 (2026-08-05)

같은 쿼리("설화수 윤조에센스" 등)를 firecrawl-local(Patchright 스텔스)로 태운 결과:

| 후보 | 결과 | 판단 |
|---|---|---|
| 네이버 쇼핑 검색 API | 서비스 종료, 신규 키 발급 불가 | ❌ |
| 네이버쇼핑 웹 (`search.shopping.naver.com`) | **로그인 벽**으로 리다이렉트 | ❌ |
| 올리브영 웹 | "브라우저 호환성" 위장 차단 페이지 | ❌ (Playwright 때와 동일) |
| 아모레몰 검색 | 차단 | ❌ (기존 `amoremall.py`도 사실상 사망) |
| SK-II 공홈 | 상품 정보 추출 0건 | ❌ (기존 브랜드 스크래퍼도 재검증 필요) |
| 에누리 | 30초 타임아웃 | ⚠️ 보류 |
| **다나와** (`search.danawa.com`) | ✅ **상품명·가격·판매처 추출 성공** | ⚠️ 단 화장품 검색 적합도가 낮음 — 광고 상품 위주로 쿼리와 무관한 결과 반환 |
| **쿠팡 파트너스 API** | 공식 제휴 API. 상품검색 + 딥링크 생성(HMAC 인증). **시간당 10회·최대 10건** 제한, 파트너스 가입 필요 | ✅ 유일한 공식·지속가능 경로 |

라이선스·지속성 판단: 스크래핑 경로는 **대부분 이미 죽었고**(로그인 벽·봇 차단),
살아있는 다나와도 ToS·차단 리스크를 계속 안는다. 반면 쿠팡 파트너스는 계약된
공식 API라 차단되지 않고, **데이터 소스와 수익 경로가 동일하다**(딥링크 수수료).

### ③ 결론

**스크래핑으로 한국 가격을 계속 긁겠다는 전제를 버린다.** 공식 제휴 API를 1차
소스로 삼고, 스크래핑은 보조로만 둔다. 새 프레임워크를 만들 필요는 없다 —
`FirecrawlBaseScraper`/`BaseScraper` 위에 소스 하나를 얹는 작업이다.

## 결정 사항

**1차 소스: 쿠팡 파트너스 API**

- 근거: 유일하게 차단되지 않는 경로 + 제휴 수익이 같은 호출에서 나온다
- 제약: **시간당 10회·10건**. 실시간 사용자 검색에 직결하면 11번째 검색부터 죽는다
- 따라서 **호출 모델을 바꾼다**: 사용자 검색 = DB 조회, 수집 = Celery beat 배치
  (시간당 10회 = 하루 240회 = 하루 2,400개 상품 갱신). compa의 본질은 "3년치
  할인 이력"이므로 축적형 모델이 오히려 제품에 맞는다

**보조 소스: 다나와** — 쿠팡에 없는 상품의 커버리지 보완용. 적합도가 낮으므로
`matcher.py`(기존 LLM 제품 매칭)를 반드시 경유시켜 오매칭을 거른다.

**폐기**: `naver_shop.py`(API 종료), `oliveyoung.py`·`amoremall.py`(차단 지속).
Delete, Don't Deprecate — 실제 삭제는 대체 소스가 데이터를 채운 뒤 별도 커밋.
