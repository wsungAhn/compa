# PRD — COMPA (2026-08-07)

> 이 문서는 프로덕트 요구사항 정의서다. "무엇을, 왜"를 다룬다. 구현 현황·함수
> 명세는 `docs/architecture-reference-2026-08-07.md`를 같이 볼 것 — 이 문서는
> 지금 존재하는 백엔드 능력을 프론트엔드가 아직 다 못 보여준다는 전제로 쓰였다.

## 1. 한 줄 정의

제품명을 입력하면 한·미·일·중 4개국의 3년치 할인 이력을 모아 "지금 살지, 기다릴지"를
추천하는 화장품 가격 비교 서비스.

## 2. 타깃 사용자

- **1차**: 기초·색조·기능성 화장품을 온라인으로 구매하는 한국 소비자(직구 포함).
  같은 제품을 한국/미국/일본 어디서 사는 게 싼지, 세일을 기다려야 하는지 궁금한 사람.
- **2차(잠재)**: 해외 K뷰티 구매자(미국·일본에서 한국 브랜드를 사려는 사람) — 크로스
  통화 비교 기능이 이 방향에도 대칭적으로 작동한다.

## 3. 핵심 가치 제안

| 질문 | COMPA가 답하는 방식 |
|---|---|
| "이 가격이 싼 건가?" | 플랫폼별 최신가 + 3년 할인 이력 그래프 |
| "지금 사야 하나, 기다려야 하나?" | 세일 캘린더(연간 반복 패턴) + YouTube 업로드 분포 기반 실측 예측 — 추측 고정일이 아니라 11년치 관측 데이터 |
| "다른 나라에서 사면 더 싼가?" | 국가 간 제품 매칭(크로스 통화) — 같은 제품이 나라마다 다른 이름으로 팔려도 하나로 묶어 환산 비교 |
| "이거 딜인가, 호구인가?" | Reddit/Slickdeals 실시간 딜 신호 + 샘플/트라이얼 오매칭 가드(가짜 "80% 할인" 걸러냄) |

## 4. 지금 실제로 서비스되는 기능 (2026-08-07 기준, 라이브)

- 제품 검색 → 3년 할인 이력 타임라인 + 가격 추이 차트
- "지금 살지/기다릴지" 추천 위젯(WaitBuyWidget) — `core/sale_calendar.py:next_sale()`이
  D-day·다음 세일명·예상 할인율까지 계산해서 이미 화면에 뜬다(직접 코드+컴포넌트
  대조 확인, 최초 조사에서 "미노출"로 잘못 적었다가 정정함)
- 플랫폼 간 가격 비교(선호 플랫폼 대비, 크로스 통화 포함 — §7-4 참고)
- Reddit·Slickdeals 딜 신호 수집(48시간 보존 강제, 사람 속도 페이싱)
- 광고 슬롯(무료 유저) + 프리미엄 키 게이팅(구독 결제 시스템은 아직 없음, 사전발급
  API 키 방식)
- 피드백 수집 + 관리자 조회
- 제휴 링크 변환(Amazon US·쿠팡·Rakuten, 3개 플랫폼만)

## 5. 만들어졌지만 사용자에게 안 보이는 것 (백엔드-프론트 격차)

세일 예측은 이미 노출된다(§4 정정) — 실제 격차는 아래 셋이다.

| 기능 | 백엔드 상태 | 프론트 상태 |
|---|---|---|
| 크로스 통화 매칭 검토 큐(`product_match_candidates`, pending/approved/rejected) | 완성, `/api/admin/product-matches` API 있음 | 없음(화면 자체가 없음) |
| 딜 신호(Reddit/Slickdeals) 원본 | 수집·저장 완성 | 노출 API/화면 없음 — SaleEvent로 흡수될 뿐, "지금 화제인 딜" 피드로는 안 보임 |
| 소셜(인스타/틱톡/페북/네이버블로그) 세일 신호 | 파이프라인 완성(API 키 있을 때만) | 없음 |
| 검색 로그(`SearchLog`) | 저장됨 | 관리자가 볼 화면 없음 |

## 6. 수익 모델 현황

- **광고**: `AdSlot` 컴포넌트로 무료 유저에게 노출(구체적 광고 네트워크 연동은
  `architecture-reference` 참고).
- **프리미엄**: 구독 결제 시스템 부재 — `X-Premium-Key` 헤더를 사전발급 키 목록과
  대조하는 방식뿐. 즉 "구매 버튼"이 없다. **이게 지금 가장 큰 수익화 공백이다.**
- **제휴 수수료**: Amazon(Luxury Beauty 카테고리 10% vs 일반 뷰티 3%, 어소시에이트
  태그 미발급 상태 — 코드는 있는데 실제 계정 연동 전), 쿠팡(TODO 상태, 실제
  Partners API 미연동), Rakuten(연동됨).

## 7. 알려진 갭 (우선순위 순 — 이 PRD의 실질적 To-Do)

1. **결제/구독 시스템 부재** — 프리미엄이 사전발급 키 방식이라 자가서비스 가입이
   안 된다. 수익화 최우선 공백.
2. **어드민 UI 부재** — 크로스 통화 매칭 검토(`product_match_candidates`), 피드백
   조회, 검색 로그 전부 API만 있고 화면이 없다. 지금은 curl/Postman으로만 운영 가능.
3. **실시간 딜 신호(Reddit/Slickdeals)가 원본 형태로는 안 보임** — 세일 예측(D-day)은
   이미 WaitBuyWidget에 노출된다(§4 정정). 다만 Reddit/Slickdeals에서 온 딜 신호는
   SaleEvent로 흡수될 뿐 "지금 화제인 딜" 같은 원본 피드 화면은 없다 — 이게
   차별화 자산인데 사용자가 그 존재를 알 방법이 없다.
4. **크로스 통화 비교 UI는 이미 있다 — 갭은 매칭 커버리지다.** `PriceComparison.tsx`가
   `cheapest_platform`/`cheapest_saving_pct`를 이미 "OO에서 약 N% 더 저렴해요"로
   렌더링한다(직접 코드 확인). 문제는 이게 **같은 `product_id` 아래 모인
   SaleEvent만** 비교한다는 것 — D단계 배치 매칭이 JP↔US 제품을 하나로 합쳐야
   비로소 이 비교가 나타난다. 지금 매칭은 6시간마다 도는 배치라 **커버리지가
   점진적**이고, 아직 병합 안 된 제품은 국가 간 비교가 그냥 안 보인다(에러가 아니라
   조용히 비교 대상이 없는 것처럼 보임 — 사용자 입장에선 "기능이 없다"와 똑같이
   느껴진다). 매칭 커버리지를 실측(전체 카탈로그 중 병합된 비율)하고 필요하면
   배치 주기를 올리거나 수동 트리거를 붙이는 게 다음 단계.
5. **라우팅 없는 단일 화면 SPA** — 딜 피드·어드민 화면을 붙이려면 최소한의
   라우팅(또는 탭 구조)이 필요.
6. **Amazon 어소시에이트 태그 미발급** — 코드는 됐는데 실제 수익 연결이 안 됨.

## 8. 범위 밖 (의도적으로 지금 안 하는 것)

- 한국·중국 소스의 완전한 크로스 통화 매칭(브랜드 사전은 있지만 라이브 검증은
  JP만 됨)
- 실시간 환율(현재 정적 테이블)
- 자체 결제 게이트웨이 신규 구축(기존 프리미엄 키 방식을 먼저 구독형으로 전환하는
  쪽이 우선순위가 높을 수 있음 — 결정 필요)

## 9. 성공 지표 (제안 — 확정 아님, 사용자 확인 필요)

- 검색 → 비교 화면 도달률
- "지금 살지/기다릴지" 위젯 클릭률
- 프리미엄 전환율(결제 시스템 생기면 측정 가능)
- 제휴 링크 클릭→구매 전환(제휴 계정 연동 후 측정 가능)
