## 이 라운드에서 배운 것

r1의 §5 커넥션 표는 **worker만 세고 API를 "동시요청 수"로 뭉뚱그렸다.** 실제로는 API가
백그라운드 수집으로 29폭을 여는 경로를 갖고 있었다. 외부 감사자의 지적 3개 중 2개
(ⓐⓑ)는 틀렸지만 나머지 하나(ⓒ)가 내 계산을 뒤집었다 — **틀린 지적이 섞여 있다고
지적 전체를 기각하면 안 된다**는 사례로 남긴다.

핵심 완화 요인도 실측으로 확인됐다: 이번 관찰 창은 API를 재시작하지 않으므로
API가 구코드(QueuePool 상한 15)를 물고 있어 **73 < 97**로 안전하다. 위험은 미래의
API 재시작에 있고, 그것을 §5.1 게이트로 문서에 고정했다.
