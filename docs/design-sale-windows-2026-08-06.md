# 설계 — 세일 창(sale_windows) 테이블 (2026-08-06)

> 소스를 늘려놨는데 **담을 그릇이 없다.** 시간축에 "어떤 브랜드가 어떤 명목으로
> 얼마만큼 세일했는가"를 붙이는 슬롯 구조가 빠져 있었다.

## 선행조사

### ① 레포 내 검색

| 있는 것 | 한계 |
|---|---|
| `sale_events` | 제품×플랫폼×가격 관측. **시간축 집계가 아니다** — "이 주에 세일이 있었나"를 물으려면 매번 스캔해야 하고, 브랜드 단위 명목(사이트와이드 25%)을 담을 자리가 없다 |
| `social_posts` | 원문 신호. Reddit은 48시간 뒤 삭제 의무 → **휘발성이라 이력이 될 수 없다** |
| `app/data/sale_timing.json` | 월 단위 12칸. 브랜드·할인폭·명목과 연결 안 됨 |
| `core/sale_calendar.py` | 규칙 기반 날짜 + 월 단위 관측. 읽기 전용 |

### ② 해상도 결정 — 실측 근거

- **365칸(일)**: 대부분 비고 노이즈만 는다. 블프는 날짜가 매년 움직인다
- **12칸(월)**: "4월 어디쯤"이라 D-day가 안 나온다(현행 `sale_timing.json`의 한계)
- **52칸(ISO 주차)**: 블프 = 11월 **넷째 주**로 주 단위에선 고정. Ulta 21 Days도
  3월 첫 주로 반복. **신호가 사는 해상도**

날짜를 아는 관측(Slickdeals·공홈)은 `observed_on`에 함께 남겨 손실을 막는다.

### ③ 결론

주차 슬롯을 1급 테이블로 만들고 **모든 소스가 같은 슬롯에 쌓이게** 한다.

## 스키마에서 비자명한 결정 4가지

초안에 없었다가 추가한 것들이다.

**1. `retailer`** — 브랜드만으로는 부족하다. 같은 Kiehl's라도 공홈 세일과 Sephora
세일은 시기가 다르고, 사용자에게 "어디서 사라"가 답이다. 이게 없으면
"Kiehl's가 4월에 세일"이 어디서인지 몰라 행동으로 옮길 수 없는 정보가 된다.

**2. `scope`** (sitewide/category/item) — 같은 25%라도 사이트와이드와 단일 품목은
값어치가 완전히 다르다. 실측된 `25% Off Sitewide: Kiehl's`가 정확히 그 사례다.
이 구분이 없으면 단일 품목 반짝 할인이 브랜드 전체 세일로 오독된다.

**3. `recurrence_key`** — 같은 행사의 연도 간 연결 키(`sephora_spring`). 반복
예측의 조인 키다. 이게 없으면 "작년 이 행사는 몇 주차였나"를 이름 문자열 매칭으로
추론해야 하는데, 명목은 해마다 문구가 바뀐다("Savings Event" → "Spring Sale").

**4. `is_estimate` / `verified`** — 관측과 추정을 섞으면 안 된다. YouTube 하울
분포는 **추정**(그 주에 영상이 몰렸다), Slickdeals·공홈은 **관측**(그 가격을 봤다).
그리고 `verified`는 앞서 세운 원칙("소셜 신호는 공홈 실가격으로 검증되기 전까지
가격으로 승격하지 않는다")의 스키마 구현이다.

## 이 구조가 푸는 것

**48시간 삭제와 이력 축적이 양립한다.** Reddit 원문(`social_posts.content`)은 48시간
뒤 지워도, 그 관측이 남긴 `sale_windows` 행("2026-W32에 Glossier 10% off,
source=reddit")은 우리 자산이다. 지워지는 건 남의 글이고 남는 건 우리가 센 사실이다.

**틀린 라벨도 자리를 갖는다.** "sephora fall sale haul"이 4월을 가리킨 관측은
W15 슬롯의 증거 하나로 들어가고, 라벨이 의심스럽다는 사실은 `source`와
`corroborations`에 남는다. 버리지 않는다.

## 범위 밖 (다음 레이어)

- 슬롯에서 **다음 세일 주차를 예측**하는 계산(연도 간 `recurrence_key` 조인)
- `sale_calendar`가 이 테이블을 읽도록 전환(현재는 JSON 파일)
- 소셜 신호 → 공홈 실가격 교차검증 → `verified=true` 승격
