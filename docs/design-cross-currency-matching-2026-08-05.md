# 설계 — 크로스 통화 제품 매칭 (2026-08-05)

> **문제**: 통화 환산은 되는데 비교 대상이 안 묶인다. 같은 SK-II 에센스가
> Rakuten(JPY)과 Amazon/공홈(USD)에서 서로 다른 product로 저장된다. 그래서
> "일본에서 사면 얼마 싸다"가 계산되지 않는다 — 서비스의 핵심 가치가 비어 있다.

## 선행조사

### ① 레포 내 검색

| 이미 있는 것 | 상태 |
|---|---|
| `ai/matcher.py:find_matching_product` — 3단계(정확일치 → brand 후보 → Claude 폴백) | **구조는 맞다.** 다만 2단계가 `brand`에 의존하는데 Rakuten 이벤트는 brand가 전부 None이라 1단계에서 끝난다 |
| `matcher.normalize_name` | 소문자·공백·태그만 처리. 프로모 노이즈·용량·언어를 다루지 않는다 |
| `_ask_claude_for_match` | 이미 구현됨. **후보를 좁혀 먹여주는 문제**이지 새로 만들 것이 아니다 |
| `collector._translate` (deep-translator) | 쿼리 번역에 이미 쓰인다 — **같은 의존성을 상품명에 재사용 가능** |
| `scrapers/brands/shopify.py:BRANDS` | 26개 브랜드 정본 목록 = 별칭 사전의 뼈대 |

### ② 외부 — 4차에 걸친 라이브 실측 (2026-08-05)

**측정 1. 식별자 조인은 불가능하다.** 라쿠텐 API 응답 필드를 전수 확인했다 —
`brand` 없음, `JAN/EAN` 없음(있는 건 상점별 `itemCode`, `genreId`). Shopify
`variants[].barcode`도 전부 `null`. **양쪽에 공통 식별자가 존재하지 않는다.**

**측정 2. 브랜드는 출처가 갈린다.**

| 출처 | 브랜드 획득 | 실측 |
|---|---|---|
| 공홈(Shopify)·Amazon | 스크래퍼가 필드로 채움 | **100%** (9/9) |
| Rakuten | 이름에서 별칭 추출 | **100%** (20/20) — 일본 판매자가 검색 노출용으로 `SKII SK-2 SK2 エスケーツー`를 다 박아둔다 |

단, 공홈 상품명은 브랜드를 포함하지 않는다(자기 매장이라 "The Water Cream").
이름 기반 추출만 쓰면 공홈이 **0%**로 나온다 — 그래서 "추출"이 아니라 **출처별
획득**으로 설계해야 한다.

**측정 3. 문자열 정규화만으로는 언어를 못 건넌다.** `Facial Treatment Essence`와
`フェイシャル トリートメント エッセンス`는 어떤 정규화로도 같아지지 않는다 —
통화 교차 그룹 **0개**. 반면 `deep-translator`로 번역하면 토큰이 실제로 겹친다.

**측정 4. 유사도 지표는 포함도여야 한다.** 자카드는 정답 쌍도 0.25로 떨어뜨렸다.
JP 리스팅은 별칭·노이즈로 토큰이 과잉이고 US 정본은 간결해서 분모만 부푼다.
**"정본 이름의 토큰이 리스팅에 얼마나 들어있나"(containment)** 로 바꾸자 정답 쌍이
**1.00**이 됐다.

**측정 5. 단위 체계가 갈린다 — 이게 조용한 킬러였다.** 미국 공홈은 `2.5 oz`,
일본은 `75ml`. 정규화 없이 "용량 일치"를 요구하면 **정답 쌍까지 전부 탈락한다**
(실측 0/10). 게다가 소수점을 흘리는 파서는 `2.5 oz`를 `5oz`로 읽는다.
`1 fl oz = 29.5735 ml`로 환산하고 ±8% 허용하자 `75ml ↔ 2.5oz(73.9ml)`가 붙었다.

**측정 6. 새 위험 — 샘플·트라이얼 리스팅.** 매칭에 성공한 그 쌍의 가격이
JP ¥1,980 vs US $99였다. 원문은 `お試し トライアル`(샘플)이다. 토큰과 용량이
정품과 같아서 통과하지만 **비교 대상이 아니다.** 이걸 그대로 노출하면 "일본이
87% 싸다"는 거짓 정보가 된다.

**측정 7. "매칭 없음"이 정답인 경우가 다수다.** JP 30ml 리스팅 6건은 대응하는
US 상품이 없다(SK-II US 최소 용량은 2.5oz=73.9ml). 0/10을 실패로 읽으면 안 된다 —
**1건 매칭 + 9건은 대응 부재/샘플**이 정확한 해석이다.

### ③ 결론

식별자 조인은 닫혔고, 문자열 정규화만으로도 안 되며, **번역 + 포함도 + 단위
정규화 3종이 모두 있어야** 한 쌍이 붙는다. 셋 중 하나만 빠져도 0건이 된다.
그리고 붙은 뒤에는 **샘플 걸러내기**가 필요하다.

## 설계

### 파이프라인 (`app/ai/matching/` 신설)

```
scraped_name
  → 1. 브랜드 획득     (스크래퍼 필드 우선, 없으면 별칭 사전으로 이름에서 추출)
  → 2. 노이즈 제거     (【公式】【送料無料】 正規品 並行輸入品 …)
  → 3. 용량 정규화     (2.5 oz → 73.9ml, 75ml → 75.0ml, 소수점 보존)
  → 4. 번역           (비영문 → 영문, deep-translator, 결과 캐시)
  → 5. 후보 좁히기     (같은 브랜드 && 용량 ±8%)
  → 6. 포함도 점수     (정본 토큰 ⊆ 리스팅 토큰, ≥0.6)
  → 7. 애매하면 Claude (후보 2개 이상일 때만 — 기존 _ask_claude_for_match 재사용)
  → 8. 샘플 가드       (가격이 정본 대비 ±X 밖이거나 샘플 키워드면 매칭 거부)
```

각 단계는 순수 함수로 분리해 개별 테스트한다. 5~7만 DB/LLM에 닿는다.

### 정본 앵커

**US 카탈로그를 정본으로 삼는다**(메인 시장이고, 공홈 `products.json`이 브랜드·
용량·정가를 구조화해서 준다). 다른 나라 리스팅은 정본에 붙인다. 현재
`product.name_kr = 유저 쿼리` 정책은 이 앵커와 충돌하므로 함께 정리한다.

### 용량은 variant에서

Shopify 스크래퍼가 지금은 최저가 variant의 **가격만** 쓰고 `title`(= 용량)을
버린다. 용량 없이는 매칭이 성립하지 않으므로 `ScrapedEvent`에 용량(ml 정규화)을
싣는다. 스키마 변경 → Alembic 마이그레이션 필요.

### 샘플 가드 (측정 6 대응)

1. 키워드: `お試し` `トライアル` `sample` `ミニ` `mini` `decant` `分装`
2. 가격 이상치: 매칭된 정본의 ml당 단가 대비 **1/3 미만이면 거부**하고
   `needs_review=True`로 남긴다(조용히 버리지 않는다 — 진짜 특가일 수도 있다)

## 검증 기준 (구현 전 고정)

`tests/ai/test_matching.py`에 실측에서 나온 실제 문자열을 그대로 넣는다.

| 케이스 | 기대 |
|---|---|
| `SK-II フェイシャル…75ml` ↔ `PITERA™ Facial Treatment Essence 2.5oz` | 매칭 |
| 같은 이름, JP 30ml ↔ US 2.5oz(73.9ml) | **거부**(용량 불일치) |
| `【公式】` `【送料無料】` 붙은 이름 | 노이즈 제거 후 동일 결과 |
| `お試し トライアル` 포함 리스팅 | **거부**(샘플) |
| ml당 단가가 정본의 1/5인 리스팅 | **거부 + needs_review** |
| 브랜드 없는 공홈 상품명(`The Water Cream`) | 스크래퍼 brand 필드로 매칭 성립 |

**오매칭은 서비스 신뢰를 직접 깎는다** — "일본이 87% 싸다"가 한 번 뜨면 그걸로
끝이다. 그래서 임계값을 낮춰 재현율을 올리는 방향으로 튜닝하지 않는다. 애매하면
매칭하지 않고 `needs_review`로 남긴다.
